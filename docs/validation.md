# Validation and limitations

| Feature               | Useful for                      | Behavior covered by tests                                                                                                                           | Edge cases                                                                          |
| --------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Errors / async routes | Consistent client failures      | Standard status factories, preserved causes, sync/async rejection, production masking, development opt-in                                           | Headers already sent delegate to Express; do not double-forward failures            |
| Responses             | Stable JSON contracts           | Success, error, pagination envelopes                                                                                                                | Caller sets HTTP status; data must be JSON-compatible                               |
| Environment           | Fail-fast startup               | Type inference, defaults, strict parsing, aggregate safe errors                                                                                     | Defaults apply only to missing variables; custom parsers enforce domain constraints |
| Request ID            | Trace concurrent requests       | Async context isolation, header validation, response IDs                                                                                            | Trust inbound IDs only through controlled ingress                                   |
| Retry                 | Transient idempotent operations | Backoff cap, jitter, predicates, exhaustion, abort, terminal errors                                                                                 | Cancellation does not forcibly stop user operations                                 |
| Shutdown              | Drain servers and dependencies  | Idempotence, cleanup failure, deadline, listener disposal                                                                                           | User closers must bound their own work; upgraded sockets need explicit cleanup      |
| Pagination            | Bounded list endpoints          | Invalid inputs, caps, overflow, zero totals, structural query adapter                                                                               | Deep offsets expensive; count/data consistency caller-owned                         |
| RBAC                  | Dynamic permission policies     | All/any matching, deny-empty, 401/403, resolver behavior                                                                                            | Authentication and tenant boundaries remain application responsibilities            |
| Logger                | Structured request-aware output | Nested redaction, errors, cycles, request context                                                                                                   | Free text and unrecognized sensitive field names require caller discipline          |
| WebSocket             | Resilient outbound connections  | Real message transport, reconnect/resubscribe, refreshed auth, retry exhaustion, ping timeout, pong success, handshake timeout, closing during auth | No offline queue, no exactly-once delivery, no browser transport                    |

This suite is a release baseline, not evidence of load testing, independent security audit, or validation against a live MongoDB cluster. The Mongoose adapter is tested against its structural query contract.
